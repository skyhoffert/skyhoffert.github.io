# General

# Code Style
- Sacrifice grammar for concise code.
- Minimal comments, only when necessary to explain tough or unclear decision.
- Do not use multiline comments e.g. "/* comment */" in C. You may in some cases use multiple single line comments when longer clarifying comments are needed.
- When the code is cleanly divided into sections or functions, use 3 empty lines to separate them, and then a section comment like "### SECTION ###".
